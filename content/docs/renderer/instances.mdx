title: Instances
description: Drawing models by reference with addModel and setInstances, at any yaw, mirrored and at fractional positions, with palettes beyond the world's 256.

Stamping writes every voxel of a model into the world's bricks. A forest of six distinct trees then
costs six trees' worth of memory per copy, a turned tree has to be resampled into new voxels, and
a moving thing re-uploads bricks every frame. **Instances** keep one copy of each model on the GPU
and draw it wherever it is placed.

## Models and placements

[`renderer.addModel(source)`](/docs/renderer/api/renderer/classes/Renderer/) uploads a model once
into the shared brick pool and returns its id. A
[`ModelSource`](/docs/renderer/api/renderer/interfaces/ModelSource/) is a size plus either dense
`data` or a [`sparse`](/docs/renderer/storage/#sparse-models) volume. Its voxel values are **role
values** (1 and up), not palette slots: each placement maps them.

`setInstances(list)` places them. Each
[`Instance`](/docs/renderer/api/renderer/interfaces/Instance/) is:

<TypeTable
  type={{
    model: { description: 'Model id from addModel.', type: 'number', required: true },
    'x, y, z': { description: 'World position of the model\'s anchor, in voxels. Fractions are allowed.', type: 'number', required: true },
    anchor: { description: 'The anchor in model voxels.', type: '[number, number, number]', default: 'base centre: size.x / 2, 0, size.z / 2' },
    yaw: { description: 'Radians about +y, any angle. Turns pivot on the anchor voxel\'s centre.', type: 'number', default: '0' },
    mirror: { description: 'Mirror along the model\'s x before turning. anchor stays the unmirrored model\'s.', type: 'boolean', default: 'false' },
    base: { description: 'Palette slot of role 1: a voxel of role r draws slot base + r - 1.', type: 'number', required: true },
  }}
/>

```ts
const oak = renderer.addModel({ size: tree.model.size, data: tree.model.data });
const oakPalette = renderer.addPalette(colours); // RGBA per role, role r at entry r - 1

renderer.setInstances([
  { model: oak, x: 120, y: 14, z: 88, yaw: 0.4, anchor: tree.model.anchor, base: oakPalette },
  { model: oak, x: 170.5, y: 16, z: 60, yaw: 2.1, mirror: true, anchor: tree.model.anchor, base: oakPalette },
]);
```

`removeModel(id)` frees a model's bricks; replace the instances naming it first.
`instanceStats()` reports models, instances, index blocks and bytes for overlays and budgets.

## How an instance is drawn

Each 64³ top cell of the world lists the instances whose box touches it. A voxel the world leaves
empty is looked up in each of them: the world point is turned into the model's space, pivoting on
the anchor voxel's centre, so a quarter turn is exact. That is resampling at world voxel centres,
so a turned instance still reads as axis-aligned cubes, the same as a baked pose. Shadows, ambient
occlusion, point lights and water need nothing special.

World voxels win where both are solid: an instance only shows where the world is empty. Empty model
bricks next to content are flagged (`NEAR_BIT`), because a ray through a rotated model cannot trust
"empty" at one brick, so it skips only where the neighbourhood is empty too.

A cell lists at most 255 instances; entries beyond that are dropped with a console warning.

### Crowded cells

Overlapping boxes make long lists: in a dense wood at 100 voxels per metre a 64³ cell lists about
20 instances, up to 75, and every step of a ray through a canopy would test them all. So every
static cell with a list also gets a table, built once with the static set. Each of its 4³
sub-cells (16³ voxels) lists only the instances that can draw a voxel there, in the cell list's
order, so the same instance wins, and masks which of its eight bricks they reach. A step then
tests two or three instances, and a ray skips bricks and sub-cells nothing reaches without asking
any model.

What an instance reaches is tight. Every occupied 2³ sub-cell of its model is turned into world
space, and a brick is marked, and the instance listed, only where a world voxel centre can sample
one of them (with a little slack for the shader's f32 rounding). A turned brick box would reach
far more of the world than its voxels do: marked from boxes, 58% of nightwood's fine steps were in
bricks marked "an instance may be here" that held no voxel.

Measured on the [nightwood](/docs/examples/nightwood/) page at 1280 × 720 on a desktop GPU, the
tight marks on every listed cell take a frame down by:

| voxels per metre | render scale 1 | render scale 0.5 |
|---|---|---|
| 20 | 31% | 29% |
| 50 | 41% | 37% |
| 100 | | 47% |

That is on top of the first tables, which were built only for cells of 8 or more instances and
marked from occupied model bricks, and which already made nightwood at 100 voxels per metre about
8 times faster than walking whole lists (2.4 fps against 0.3 at full scale).

The cost is build time. The tables are built on the main thread in `setInstances` (or on a worker,
see [below](#baking-the-static-set-on-a-worker)): on nightwood
about 0.65 s at 20 voxels per metre, 5 s at 50 and 20 s at 100 (it was 0.17, 1.3 and 6 s with
brick marks). Their index region ("subs") stays about the same size at 20 and 50 (1.5 and
14.5 MiB) and grows from 83 to 93 MiB at 100.

Cells a dynamic instance touches fall back to their whole list while it is there, as does any cell
over the 255 cap.

### Matching stamped orientations

The engine stamps models in eight axis-aligned orientations (four quarter turns, optionally
mirrored). An instance with `yaw = -(o & 3) * π / 2` and `mirror = (o & 4) !== 0` draws exactly
what stamping with orientation `o` would; the engine's
[`orientationYaw(o)`](/docs/engine/api/engine/functions/orientationYaw/) returns that pair.

## Static and dynamic sets

There are two sets of instances, sent separately:

- **Static** (the default), for scenery: `setInstances(list)` replaces the static set and builds its
  per-cell lists and their sub-cell tables once.
- **Dynamic**, for a crowd: `setInstances(list, { dynamic: true })` replaces only the moving set,
  every frame. Its cost is the moving instances and the cells they touch, however much scenery
  there is: moving instances go after the static ones, each cell they touch gets a fresh list (its
  static entries, then the moving ones), and cells they left get their static entry back.

```ts
// Once, behind the loading screen: the scenery (lists and sub-cell tables built here).
// oakId and ratId come from addModel, the palettes from addPalette.
renderer.setInstances(trees.map((t) => ({ model: oakId, x: t.x, y: t.y, z: t.z, yaw: t.yaw, anchor: oakAnchor, base: oakPalette })));

// Every frame: only what moves. The static set is left as it is.
renderer.setInstances(
  rats.map((r) => ({ model: ratId, x: r.x, y: r.y, z: r.z, yaw: r.yaw, anchor: ratAnchor, base: ratPalette })),
  { dynamic: true },
);
```

Instance sampling is a pipeline constant. A scene that never places an instance runs a shader with
that code compiled away (it costs even when never taken: several times the frame on SwiftShader),
and the instanced pipeline is built the first time one is placed, in the next frame's `render`.
[`prepare()`](/docs/renderer/api/renderer/classes/Renderer/#prepare) compiles it ahead instead (see
[Entry points](/docs/renderer/entry-points/#warming-the-pipelines-up)).

### Baking the static set on a worker

A static `setInstances(list)` is a headless **bake** (the instance records, packed poses, per-cell
lists and sub-cell tables) followed by a cheap **apply** that copies the result into the
renderer's buffers. The two halves are public, so the bake can run on a worker while the main
thread keeps drawing:

| step | where | API |
|---|---|---|
| send each model's placement data once, after `addModel` | main thread → worker | [`placementModel(id)`](/docs/renderer/api/renderer/classes/Renderer/#placementmodel) → [`PlacementModel`](/docs/renderer/api/renderer/interfaces/PlacementModel/) |
| take the bake's input for a static set (a cheap copy of the list) | main thread | [`placementInput(list)`](/docs/renderer/api/renderer/classes/Renderer/#placementinput) → [`PlacementInput`](/docs/renderer/api/renderer/interfaces/PlacementInput/) |
| bake it | worker | [`PlacementBaker`](/docs/renderer/api/renderer/classes/PlacementBaker/)`.bake(input, opts?)` or [`bakePlacement(input, lookup, opts?)`](/docs/renderer/api/renderer/functions/bakePlacement/) → [`PlacementBake`](/docs/renderer/api/renderer/interfaces/PlacementBake/) |
| report progress (optional) | worker → main thread | [`PlacementBakeOptions`](/docs/renderer/api/renderer/interfaces/PlacementBakeOptions/)`.onProgress(done, total)` |
| send it back without copying | worker → main thread | `postMessage(bake, placementTransferables(bake))` ([`placementTransferables`](/docs/renderer/api/renderer/functions/placementTransferables/)) |
| draw it | main thread | [`applyPlacement(bake)`](/docs/renderer/api/renderer/classes/Renderer/#applyplacement) |

`setInstances` runs this same code on the main thread, so both paths upload the same bytes. The
bake half imports nothing that needs a DOM, a GPU or a bundler: import it from
`@voxolith/renderer/core` in the worker. Model data is sent once per model, keyed by a
registration key that is unique on the page and never reused; `applyPlacement` checks those keys
and throws when a model the bake names was removed or replaced since `placementInput` (bake again
then), or when the bake is for another renderer's grid. The moving set stays and is redrawn on
top, and the old static set draws until the apply.

<Tab value="main thread">

```ts
import type { Instance, PlacementBake } from "@voxolith/renderer";

const worker = new Worker(new URL("./placement.worker.ts", import.meta.url), { type: "module" });

// Each model once, after addModel; its key again after removeModel.
const oak = renderer.addModel({ size: tree.model.size, data: tree.model.data });
worker.postMessage({ type: "model", model: renderer.placementModel(oak) });
function removeTree(id: number): void {
  const key = renderer.placementModel(id)?.key;
  renderer.removeModel(id);
  if (key !== undefined) worker.postMessage({ type: "drop", key });
}

// The static set: take the input here, bake there, apply the newest result.
let latest = 0;
let scenery: Instance[] = [];
function placeStatic(list: Instance[]): void {
  scenery = list;
  worker.postMessage({ type: "bake", id: ++latest, input: renderer.placementInput(list) });
}
type Reply = { id: number; done: number; total: number } | { id: number; bake: PlacementBake };
worker.onmessage = ({ data }: MessageEvent<Reply>) => {
  if (data.id !== latest) return; // superseded
  if (!("bake" in data)) {
    bar.value = data.done / data.total; // opaque units: only the fraction means anything
    return;
  }
  try {
    renderer.applyPlacement(data.bake);
    loop.invalidate();
  } catch {
    placeStatic(scenery);          // a model it names was removed meanwhile: bake without it
  }
};
```

```ts title="placement.worker.ts"
import { PlacementBaker, placementTransferables, type PlacementInput, type PlacementModel } from "@voxolith/renderer/core";

type Message =
  | { type: "model"; model: PlacementModel }
  | { type: "drop"; key: number }
  | { type: "bake"; id: number; input: PlacementInput };

const baker = new PlacementBaker();
self.onmessage = ({ data }: MessageEvent<Message>) => {
  if (data.type === "model") baker.register(data.model);
  else if (data.type === "drop") baker.unregister(data.key);
  else {
    const onProgress = (done: number, total: number) => self.postMessage({ id: data.id, done, total });
    const bake = baker.bake(data.input, { onProgress }); // (0, total) first, (total, total) last
    self.postMessage({ id: data.id, bake }, { transfer: placementTransferables(bake) });
  }
};
```

</Tab>
</Tabs>

`onProgress` counts opaque work units, so only `done / total` means anything: the first call is
`(0, total)`, the last `(total, total)` just before the bake returns, and in between at most one
every 50 ms or so. The count moves only between instances, so at fine scales it advances in steps
(about 190 ms apart at 100 voxels per metre). Without `onProgress` the bake does no progress work.

Messages to one worker are handled in order, so a `drop` or a new `model` posted before a `bake`
is seen before it. The engine's [`servePlacement`](/docs/engine/api/worker/functions/servePlacement/)
adds cancelling a bake that has not started, and error replies.

The engine wraps all of it: `makePlacementWorker` and `makeInstanceLayer(renderer, { placement })`
with `commitAsync()` (see [From the engine](#from-the-engine) and the manual's
[placement off the main thread](/docs/manual/managing-loading/#placement-off-the-main-thread)).

## Instance palettes

Instances draw from palettes of their own, stored after the world's 256 slots (`WORLD_SLOTS`) in
the same buffer. World voxels are 8-bit, so they can only name the first 256; instances name a
`base` of any size.

| method | does |
|---|---|
| `addPalette(colors, materials?)` | a new palette; `colors` is RGBA per entry, `materials` optionally 8 floats per entry. Returns the base slot |
| `setPaletteColors(base, colors, materials?)` | recolour in place: every instance using it changes |
| `removePalette(base, entries)` | free it; instances still naming it draw garbage colours |

The buffer grows as needed, so a scene is not limited to 255 colours: every species, or every
placement, can have its own palette, and restyling one (a season, a faction, damage) is one
`setPaletteColors` call. An instance may also use the world's palette by passing a world `base`.

## From the engine

The engine drives all of this for entities:

- [`makeInstanceLayer(renderer)`](/docs/engine/api/engine/functions/makeInstanceLayer/) uploads
  each `EntityModel` once (by identity), keeps static placements apart from moving ones and sends
  both, and its `palettes.of(key, roles, tint?)` makes and caches instance palettes from colour
  roles.
- [`makeCrowd({ instances })`](/docs/engine/api/animation/functions/makeCrowd/) places animated
  members as pose models, with a pose cache and distance LOD.

```ts
import { makeInstanceLayer } from "@voxolith/engine";

const layer = makeInstanceLayer(renderer);
const base = layer.palettes.of("oak", tree.model.roles);
layer.setStatic([{ model: tree.model, x: 120, y: 14, z: 88, yaw: 0.4, base }]);
layer.commit(); // sends the static and moving sets; cheap to call every frame
```

`setStatic` takes entity models rather than ids and places each on the model's own anchor. Given a
placement worker, `layer.commitAsync()` bakes the static set there
([Engine: instances](/docs/engine/instances/#baking-on-a-worker)).

See [Instances](/docs/engine/instances/) in the engine section for the layer, and
[Stamping and crowds](/docs/engine/stamping-and-crowds/) for when to stamp instead.

## Posed on the GPU

A model added with **parts** (one part index per voxel, beside its role values) can be drawn with
one transform per part instead of one per instance: pose a skeleton on the GPU from a single rest
model, with nothing baked. The renderer takes each world cell back through every part's inverse
into the rest model; the first part whose own voxel is there wins, parents first, and the cells
around each joint may be filled from either side (a weld), so a turned limb stays on.

```ts
const id = renderer.addModel({ size, data, parts, joints }); // joints: parent and meeting point per part
renderer.setInstances(
  [{ model: id, x, y, z, anchor, yaw, base, parts: boneMatrices }], // 12 floats per part, model space
  { dynamic: true },
);
```

Each such instance is a single entry in the per-cell lists. Its pose (the part inverses, joints and
a small grid of part masks, two 32-bit words per 8³ brick of the posed model saying which parts can
be in the brick and which joints weld there) lives in the model's own space, so the renderer packs
and uploads it once, keyed by the part transforms' identity, and every instance showing it shares
it; per frame an instance costs its record. The masks let a sample test one or two parts and a ray
skip the bricks no part reaches. Pass `partBoxes` to `addModel` (e.g. an undamaged model's) so
damaged copies share poses too.

Limits:
- **A dense model.** `addModel` takes `parts` only beside dense `data`, not a `sparse` volume.
- **At most 32 parts.**
- **Rigid parts.** Each voxel follows exactly one part; there is no smooth (skinned or cage)
  deformation between parts beyond the weld at each joint.
- **Measured on a desktop GPU only.** Posing on the GPU has not been measured on a phone yet.

The engine drives this from a rig: `prepareRigged` and
`makeCrowd({ instances, rigged: true })` ([stamping and crowds](/docs/engine/stamping-and-crowds/#posed-on-the-gpu)).

Instances also take a full `rotation` (a 3x3, row-major) instead of `yaw`: tumbling debris, a
tilted placement.
